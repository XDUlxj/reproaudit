# SciTrace V2 运行时状态

State 只保存 graph 后续步骤需要继续读写的当前事实、必要编排控制和明确返回值。
业务历史与审计记录属于 Persistence / Trace；一次调用固定的依赖与委派参数属于
Runtime Context / Input。

## Main State

```python
from typing import Literal

from langgraph.graph import MessagesState

from scitrace.models import ExperimentRun, ExperimentSpec, ResearchResource


class SciTraceState(MessagesState):
    """跨 Specialist 共享的当前事实、编排约束与 graph 输出。"""

    task_id: str
    resources: list[ResearchResource]
    experiment_spec: ExperimentSpec | None
    experiment_run: ExperimentRun | None
    required_specialist: Literal[
        "discovery",
        "analysis",
        "execution",
    ] | None
    final_answer: str | None
```

- `messages`：SciTraceAgent loop 的消息状态。
- `task_id`：关联持久化业务记录的稳定标识。
- `resources`：已经确认、可供后续 Specialist 使用的当前资源工作集。
- `experiment_spec`：当前有效 Spec；历史版本由 Persistence 保存。
- `experiment_run`：当前关注的 Run；历史运行由 Persistence 保存。
- `required_specialist`：确定性下一跳约束，不表示固定阶段或当前 Agent。
- `final_answer`：当前 graph run 最终返回给调用方的输出。

## Specialist State

Walking Skeleton 阶段的三个 Specialist 均使用 LangChain/LangGraph 标准 message state。
主图通过 Agent-as-Tool 的调用输入传递目标和必要事实，不提前定义 Specialist 自定义 State。

只有某个 Specialist 的内部数据确实需要跨多个 node、tool 或 middleware 结构化读写，且不应
提升为跨 Specialist 事实时，才为它增加专属 State。

## 明确不放入 Main State

- candidate、search history、retry/recovery 等 Specialist 内部过程数据；
- execution budget、历史 Spec、历史 Run 与审计日志；
- phase、current/next agent、workflow status 等固定流水线字段；
- DiscoveryResult、AnalysisResult、ExecutionResult 等单次 Tool 返回对象。
