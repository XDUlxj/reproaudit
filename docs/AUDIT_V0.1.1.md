# SciTrace v0.1.1 仓库查验

日期：2026-09-15。查验涵盖架构、CLI、Agent、模型、持久化、检索、下载、执行、验证、报告、测试和交付文档。

## 结论

已完成一个真实服务、真实 Docker 的 Cooking 教程闭环，并保留论文、发现、仓库、Trace、计划、审批、执行、验证及模型产物。不是替身模型演示，也不是原论文 benchmark 验证。该任务在修复过程中跨进程恢复；最后的任务终态根据成功账本协调，未重新执行实验。

不能把这个案例通过外推为“任意论文自动复现”或“v0.1.1 所有原始质量目标均全面验收”。通用规划、科学关联质量及多案例稳定性仍需后续评估。

## 逐项检查

| 项目 | 结论 / 修复 | 验证边界 |
| --- | --- | --- |
| 架构 | 保留 LangGraph 动态 Supervisor 和 Discovery/Trace/Execution 三个独立循环 | 简单问答和已有计划均不强制固定流水线；Cooking 为可选配方 |
| 工具调用 | 任务内持久化短引用；参数解码后仍保存完整 ID | 单测验证重启映射；模型仍可能传错字段，不模糊猜测引用 |
| 状态与完成 | `--require-execution`；成功账本+验证记录确定单实验完成；未执行不能成功结束 | 不支持把此条件外推到多实验目标 |
| 循环收敛 | 预算、重复动作/错误/读取限制；配方保存成功直接返回持久 Trace | 无进展判断仍有改进空间，通用规划成功率尚未统计 |
| 论文 | 本地路径授权归一化、NUL 等长替换、原 PDF 保存 | 真实页码和原文回查通过；公式字体/复杂表格仍需人工核对，OCR 不支持 |
| 检索 | exact/BM25/vector 融合；仓库文本/文件名/Python AST；Trace 获得专用仓库搜索工具 | 真实 E5/Qdrant 已调用；非 Python AST 不支持 |
| 仓库 | URL 别名保存正确 resource_id；显式不可变提交可复用缓存或直接下载快照 | GitHub API 403 不冒称 HEAD；本次固定提交为 1142dc4… |
| Discovery | 合法类型 schema、URL 与资源 ID 校验、未核实官方身份降级 | 本次仓库为 unverified，经明确审批使用；不能称来源身份已自动证明 |
| 计划 | 核验 SHA256；禁止 paper_only 携带实验命令；检查直接 shell 操作符和联网命令 | 非全面命令语义证明，shell/python 内部仍依赖计划审阅和容器隔离 |
| Cooking 配方 | 实际检索论文/代码/教程、固定数据摘要、12404/3000 划分、默认训练、2线程 | 仅此配方作工程验收；无预设科学阈值，不报告 benchmark verified |
| 持久化 | PostgreSQL 业务表与 checkpoint；所有新写入字典默认 schema_version | 不覆盖旧数据、不恢复已删除 reproaudit |
| 审批恢复 | 资源、计划、镜像分别绑定摘要；三次批准和独立进程 resume | 真实恢复成功；拒绝与变更隔离以单测验证 |
| 执行隔离 | 非 root、断网、只读根、无 capabilities、2 CPU/4GiB/600秒、tmpfs | 真实 Docker 编译/训练/测试通过；不是公共多租户恶意代码沙箱 |
| 产物导出 | 修复 Docker cp 未导出 tmpfs；改为容器 tar 流+安全解压 | 真实 tmpfs 测试与模型 .bin/.vec 摘要通过 |
| 幂等 | 已执行账本不重跑；状态不明禁止自动重复 | 成功任务跨进程状态协调没有新增执行；运行中崩溃场景以单测覆盖 |
| 下载 | DNS 固定、逐跳校验、预算、有限重试、单次总时限；真实缓存重算 SHA256 | 外网代理仍可能失败；不自动放开新域名 |
| 安全解压 | 拒绝路径越界、链接、特殊文件、体积超限；流式写文件 | 单元恶意归档测试；真实产物导出走相同边界 |
| 自动修复 | 有限网络重试和确定性工程修复 | 任意依赖升级、代码修补不自动执行；未实现无限修复 |
| 验证器 | 独立规则比较，缺条件/教程返回 not_tested | 真实指标与日志一致；失败不等于科学证伪 |
| 报告 | 任务证据池、缓存论文引用、仓库版本、下载核验、审批、命令、指标、产物 | 执行结论来自账本；一般 Claim 的学术正确性仍需人工审阅 |
| 依赖与交付 | pyproject/uv.lock 版本 0.1.1、中文 README、迭代记录、核验脚本 | `.env` 密钥不写入交付文档；历史已暴露密钥的服务端轮换仍由用户完成 |
