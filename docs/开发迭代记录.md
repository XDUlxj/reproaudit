# SciTrace V2 开发迭代记录

## 迭代 1：工程骨架与领域模型

- 已完成：创建分层目录与 Python 工程配置。
- 已完成：实现 Task、ResearchResource、ExperimentSpec、ExperimentRun 领域模型。
- 已完成：为判别联合、生命周期和 Artifact 哈希增加基础测试。

## 迭代 2：Persistence 第一版

- 已完成：使用 SQLAlchemy 2.x 实现 PostgreSQL/SQLite 共用表结构。
- 已完成：实现四类 Entity 的 Repository，支持稳定 ID 幂等重放和冲突检测。
- 已完成：实现 Task–ResearchResource 关联、Spec 版本关系和 Run 生命周期更新。
- 已完成：实现 PostgreSQL 启动探活失败后的显式 SQLite 降级。
- 已完成：为 SQLite 开启外键约束，使测试行为尽量与 PostgreSQL 一致。
- 已完成：实体快照在 PostgreSQL 使用 JSONB，SQLite 降级时使用兼容 JSON。
- 已完成：Task 的 answer 使用独立 TEXT 列，便于直接展示与查询。
- 边界：本轮没有持久化 Agent State、Message、检索索引或 Artifact 文件内容。
- 待办：接入 Alembic migration，增加真实 PostgreSQL 集成测试。
- 下一步建议：实现应用服务层的明确业务提交点，再接 Agent-as-Tool wrapper。

## 迭代 3：Retrieval + Ingestion 最小闭环

- 已完成：定义 ContentLocator、ResourceChunk、RetrievalHit DTO。
- 已完成：本地 Paper/Repository resolve 与确定性 PDF/仓库文本解析。
- 已完成：保留页码/文件行号的确定性分块。
- 已完成：FastEmbed multilingual dense + Qdrant/BM25 sparse 编码适配器。
- 已完成：Qdrant named vectors、resource_id payload index、RRF 混合检索。
- 已完成：按 resource_id 先删后写的幂等 ingestion 重建。
- 边界：V1 默认只全文索引 Paper/Repository，Web 资源必须先 materialize 到本地。
- 待办：真实模型下载与外部 Qdrant 服务集成验证、Retrieval Eval 数据集。
